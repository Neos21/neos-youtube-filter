# Review Feedback Rules

レビュー指摘を反映する際に、同じ問題の再発を防ぎつつルールの無制限な増加を避ける。


## 指摘の分類

1. ESLint、型、Schema、テストで機械的に防げる
    - 文書ルールを追加する前に自動化を検討する
2. 複数タスクで再発しうる全体ルール
    - 既存ルールを更新し、適切な Agent Rule に統合する
3. 特定領域だけに適用される
    - Frontend、Backend、Shared、Documentation の該当ファイルに追加する
4. 設計判断と理由を残す必要がある
    - Architecture (`ARCHITECTURE.md`) または ADR (`docs/decisions/`) に記録する
5. 今回だけの入力ミス・単発判断
    - 恒久ルールに追加しない


## 追加・更新方針

- 同じ原因を扱う既存ルールがある場合は、新しい箇条書きを増やさず既存ルールを明確化する
- 禁止事項だけでなく、安全な代替実装が分かる表現にする
- 適用範囲と例外が曖昧なルールを追加しない
- 現行コードやツールで不要になったルールは、開発者に確認のうえ統合または削除する
- レビューごとに機械的に追記せず、再発可能性と一般化可能性を判断する
