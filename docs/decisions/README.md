# ADR : Architecture Decision Records (アーキテクチャ意思決定記録)

将来も参照する価値がある設計上の選択と、その理由・影響を記録する。現行仕様そのものは `README.md`、`ARCHITECTURE.md`、Domain、Feature 文書に記載し、ADR には「なぜその方式を選んだか」を残す。


## 一覧

|------------------------------|------|-----------------------------------|
| [ADR-000](./000-template.md) | 雛形 | 新しい ADR を作成する際の記載項目 |


## 追加基準

- 複数の実装案から選択し、却下案やトレードオフを将来知る必要がある
- 複数機能・複数レイヤーに影響する
- 後から見て理由なしに変更すると、整合性や保守性を損なう

関数の処理順や実装意図など、コードの近くにある方が理解しやすい情報は ADR にせず、ソースコードのドキュメンテーションコメントに記載する。

新しい ADR は [ADR-000](./000-template.md) を複製し、3桁の連番を付けて作成する。見出しは英語と日本語を併記し、状態は日本語のみで記載する。
